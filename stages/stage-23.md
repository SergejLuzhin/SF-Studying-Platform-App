## Цель и границы

Подготовить в `README.md` воспроизводимую русскоязычную инструкцию по существующей учебной платформе и её REST API. Пользователь отдельно разрешил минимально исправить блокирующий дубликат `spring.config` в `application-dev.yml` и добавить регрессионные тесты запуска. Иные изменения конфигурации, бизнес-логики, инфраструктуры и публичного API в этап не входят; другие дефекты передавать главному агенту.

## Приёмка и проверочные сценарии

- Новому читателю доступны локальный и Docker запуск, настройки, тесты, демонстрация, основные REST-маршруты и точные необходимые команды; результаты зависят от фактических ID, а не от предположения об их значениях.
- На пустой изолированной БД демонстрационные данные создаются только при явном выборе `demo`, повторный запуск не создаёт дубликаты; видны курс, студент, задание и вопросы. Проверить прохождение и получение результата, а также типы и статусы ответов.
- Регрессионный тест загружает именно исходный `application-dev.yml`: `dev` стартует без `DuplicateKeyException`, с `ddl-auto: update`, без бина сидера и без демонстрационных данных; `dev,demo` стартует на той же изолированной PostgreSQL, запускает сидер и создаёт данные; после закрытия и нового старта `dev,demo` количества основных демонстрационных сущностей и маркера не увеличиваются. Проверить реальный URL подключённой БД и отсутствие активного профиля `test`. Ошибка старта, применение другой конфигурации или обращение к рабочей БД недопустимы.
- Проверить пустой и непустой список; отсутствие ресурса — 404; невалидное тело или несоответствие `lessonId` — 400 с фактической структурой ошибки; `PUT` с другим `lessonId` не меняет родителя.
- Проверить создание тега, прикрепление и открепление от курса, удаление тега с сохранением курса; проверить, что `/start` не содержит признака правильности, но административный ответ варианта может его содержать.
- Проверить запрет повторной записи или сдачи, поведение неготового теста и запрет удаления курса с историей после отписки; успешное удаление отдельного курса без истории не удаляет общие объекты.
- Проверить наличие в README явного предупреждения об отсутствии обоих механизмов безопасности и о доступности административных операций любому клиенту API.

## Команды проверки

Выполнять только после подготовки изолированной базы и проверки Docker; проверки HTTP и запуска выполнить буквально по итоговому README, включая повторный запуск демо. Приведённые ниже команды подтверждены существующими `pom.xml`, CI или тестовыми классами:

```bash
mvn -B clean compile
mvn -B test
mvn test -Dtest=DemoDataSeederTest,RestApiTests,RestAcceptanceTest,LazyLoadingAndCascadeTests,CourseDeletionTests,DockerInfrastructureTest
mvn -B package
docker compose config
docker compose up --build
git diff --check
```

`mvn -B test` включает новый регрессионный тест после его создания. `mvn -B package` выполняет тесты и требует доступного Docker. Для ручного подтверждения локальной инструкции использовать существующую команду `mvn -B spring-boot:run -Dspring-boot.run.profiles=dev -Dspring-boot.run.arguments=--server.port=0`, затем аналогично с `-Dspring-boot.run.profiles=dev,demo` и повторить второй запуск; заранее явно задать `DB_URL`, `DB_USER`, `DB_PASSWORD` для отдельной пустой PostgreSQL, убедившись в адресе базы. Между запусками корректно остановить приложение; не направлять `update` на `studying_platform_v2`. `docker compose up --build` запускается после сборки JAR и занимает терминал; не использовать команды удаления томов или очистки чужих данных. Дополнительно сверить вывод `git diff -- README.md` и фактические HTTP-ответы с примерами. Проверки на данном этапе планирования не запускались; результаты должны быть отмечены `PASS`, `FAIL` или `NOT_RUN`.

## Риски и блокеры

- Дубликат ключа исправлен с разрешения пользователя; независимые запуски `dev` и `dev,demo` уже отмечены `PASS` в `state.md`. Это не заменяет незавершённые ручные HTTP-проверки, буквальное воспроизведение README и ручное сравнение количеств.
- Для демо недостаточно просто совпадения маркера: возможны конфликты других уникальных данных и частичный набор. Использовать новую изолированную БД и явно сообщить об ограничении.
- Локальный PostgreSQL, Docker daemon, скачивание образов и свободный порт 8080 — внешние предпосылки. При недоступности фиксировать `NOT_RUN` и не считать обязательную воспроизводимость доказанной.
- Docker Compose содержит учебные пароли и не объявляет постоянный том; не рекомендовать его как защищённое производственное развёртывание.
